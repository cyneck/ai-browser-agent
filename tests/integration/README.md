# 集成测试

## 概述

本目录包含集成测试，用于验证各组件在真实环境下的协同工作能力。与单元测试不同，集成测试使用真实的依赖项而非mock对象，以确保组件间交互的正确性。

## 测试策略

### 单元测试 vs 集成测试

1. **单元测试**（位于[tests/unit](file:///D:/code/ai-browser-agent/tests/unit)）：
   - 目标：测试单个组件的功能
   - 依赖项：使用mock对象模拟
   - 执行速度：快
   - 环境要求：低，无需真实浏览器或网络连接

2. **集成测试**（本目录）：
   - 目标：测试多个组件的协同工作
   - 依赖项：使用真实的组件和外部服务
   - 执行速度：较慢
   - 环境要求：需要真实浏览器环境

### 何时编写集成测试

只在以下情况下编写集成测试：
1. 测试涉及多个组件的真实交互
2. 需要验证与外部服务（如浏览器）的集成
3. 单元测试无法覆盖的关键路径
4. 复杂的端到端场景

### 集成测试原则

1. **必要性**：仅对无法通过单元测试验证的关键集成点编写集成测试
2. **速度**：尽量保持测试快速执行，避免不必要的延迟
3. **稳定性**：确保测试在不同环境下稳定运行
4. **隔离性**：每个测试应独立运行，不依赖其他测试的结果

## 运行测试

```bash
# 运行所有集成测试
pytest -m integration

# 运行特定集成测试文件
pytest tests/integration/test_page_analyzer_integration.py -m integration

# 运行所有测试（包括单元测试和集成测试）
pytest
```

## 测试环境

集成测试需要以下环境：
- Chromium浏览器（通过Playwright提供）
- 网络连接（用于访问外部测试站点）
- 文件系统访问权限（用于创建临时文件）

## 最佳实践

1. 使用headless模式运行浏览器以提高执行速度
2. 在测试结束后正确清理资源（浏览器实例、临时文件等）
3. 使用临时文件和唯一标识符避免测试间的冲突
4. 对外部服务的依赖应有适当的重试和超时机制
5. 优先使用可靠的测试站点（如httpbin.org）而不是生产环境
